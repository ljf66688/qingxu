# 中文离线精简版：第一版确认方案

更新日期：2026-10-16。基础项目：OpenNutriTracker。用户已确认开始开发，第一版功能已实现；构建、验证和食物库实际范围见[离线版说明](离线版开发与使用说明.md)。使用对象一项由用户明确保留未选，不预设仅供个人使用，也不将其视为公开分发授权。

## 用户已确定的范围

- 安卓中文应用，离线优先，食物以粤菜为主。
- 早餐、午餐、晚餐分别记录各种食物的摄入热量。
- 添加食物时搜索名称，展示每100克热量；输入实际食用克数后自动换算，再加入指定餐次。
- 用户资料用于估算基础代谢。
- 用户自行填写今日运动消耗热量。
- 收藏常吃的食物，方便下次添加。
- 热量统计支持每日、每周、每月查看。

## 建议采用的交互

首页“今日”顶部显示三项：今日总摄入、基础代谢估算、今日运动消耗。下方为早餐、午餐、晚餐三张卡片，每张显示食物、克数、该项热量和餐次合计。

添加食物流程：点击某餐的“添加” → 查看搜索/收藏/最近吃过 → 搜索并选中食物 → 查看每100克热量和计量说明 → 输入克数 → 即时显示本次摄入热量 → 确认加入该餐。默认先选择食物，再填写克数，不要求用户自行计算热量。

食物条目可以修改克数、删除；食物克数或条目变化后，每餐和全天合计立即更新。收藏保存的是食物本身，下次使用仍可重新填写克数；“最近吃过”保留上次克数作为可修改的快捷值。

## 讨论后已确认的设计原则

- 粤菜默认热量是来源明确的参考值。用户可修改每100克热量并保存自己的版本，保留原始参考值供恢复。
- 没有秤时允许填写估算克数，并为该条记录显示“估算”标签。
- 设置“当天已记录完整”操作，周/月日均只计算用户标记完整的日期。
- 即使包含估算克数，只要当天饮食记录齐全，仍可标记完整；完整性与是否实际称重分开表达。
- 食物热量修改只影响以后添加的条目。过去条目保存当时的克数和每100克热量快照，用户仍可单独编辑过去某条记录。
- 收藏及最近食物的录入流程，以普通一餐能在一分钟内录完为第一版验收目标，需实际使用验证。
- 使用对象不在本轮确定，不将“仅供用户个人使用”作为范围限制；账号、云服务、公开发布或上传商店仍不在已授权实施范围内。

底部建议采用“今日 / 统计 / 收藏 / 我的”四个入口。食物搜索位于添加流程，个人资料位于“我的”。

## 每日、每周、每月热量统计

统计页提供“日 / 周 / 月”切换，默认定位当前日期所在周期，可查看以前的日期、周和月份。按设备本地日期归属记录；每周默认周一至周日，每月按自然月划分。

| 周期 | 展示内容 |
| --- | --- |
| 每日 | 早餐、午餐、晚餐摄入明细及小计，全天总摄入，当天已记录运动消耗 |
| 每周 | 本周已记录总摄入、完整记录日的日均摄入、运动总消耗、完整/有记录天数，以及按天排列的热量柱状图 |
| 每月 | 本月已记录总摄入、完整记录日的日均摄入、运动总消耗、完整/有记录天数，以及按天排列的热量趋势 |

周/月总摄入为该周期内全部食物条目的热量之和，包含尚未标记完整的日期。日均摄入 = 周期内标记完整的日期的摄入之和 ÷ 标记完整的日期数，旁边明确显示完整记录和已有记录的天数。不完整日期的摄入既不进入日均分子，也不进入分母。仅有运动记录的日期不自动标记为饮食完整。没有完整记录日时，日均显示“暂无完整记录”，不做除零计算。

例如三天完整记录分别为2000、1900、2100千卡，另一天只记录500千卡早餐：周已记录总摄入为6500千卡，完整日的日均为2000千卡，而不是用6500除以3或4。估算条目若所在日期已标记完整，则与称重条目一样参与完整日统计，并保留估算标签。

未记录的日期显示为空缺，不自动当成零摄入；当前周期尚未到来的日期不计入记录完整度的分母。周/月运动总消耗按对应周期的手填运动记录独立汇总，不用运动数值抵扣“总摄入”。修改或删除某一天的食物/运动记录后，相应日、周、月统计同步更新；点击图表中的某天可查看当天明细。

周/月汇总保留原始条目精度后再舍入显示，不将已舍入的每日显示值反复累加。跨周、跨月和跨年边界按实际日期处理。

## 建议加入的必要补充

1. **年龄字段**：资料包括性别、年龄或生日、身高cm、体重kg；常用基础代谢相关估算公式需要年龄，不使用隐藏默认年龄。
2. **明确食物状态与范围**：名称显示“熟米饭”“白切鸡（可食部分）”“白切鸡饭（含米饭）”，不把生料、单菜和套餐混在一个结果里。带骨肉类的克数以实际吃下的可食部分为口径，并在条目说明。
3. **搜不到时可自行添加**：只需名称与每100克热量，保存到个人食物库，随后可搜索、收藏、按克数计算。第一版无需复杂菜谱编辑器。
4. **运动消耗不改变摄入总数**：手填今日运动kcal，可修改、清空；分别显示摄入和运动，避免将摄入减去运动后的数称为“总摄入”。
5. **全部核心功能离线可用**：首次启动、粤菜本地搜索、收藏、记录、计算和个人数据在本地运行，无需账号或服务器。食物数据保留来源和版本。

“最近吃过”属于便利性优化，建议随收藏一起加入；其余扩展如拍照识别、手表同步、云账号、复杂菜谱编辑暂不进入第一版。

## 粤菜食物库

建议第一批以约100个经过逐项核验的条目为目标，以实际核验通过数量为准，不承诺未经检查的固定数量。覆盖常见主食、粥粉面饭、蒸煮菜、家常肉菜、烧味、蔬菜和点心。除了粤菜，还要提供米饭、鸡蛋、牛奶等常见基础食品，便于完整记录一日三餐。

检索名称兼容常见写法，例如“白切鸡/白斩鸡”“河粉/沙河粉”“炒蛋/炒鸡蛋”；同义词只辅助搜索，不把不同烹饪方式的食物强行合并。无糖/加糖、清蒸/油煎、去皮/带皮在能量差异明显时分为不同条目。

优先评估的开放数据来源：Long等人的500道粤菜研究记录，收录于包含500道川菜和500道粤菜的数据集；Figshare元数据标注CC BY 4.0。该来源的营养值是依据配方食材估算的，不是所有餐厅成品菜的实测常数。需逐项检查热量是每份还是每100克、原料重还是成品熟重、有无可用的熟重，再决定能否作为每100克条目。[研究论文](https://doi.org/10.1038/s41597-025-05871-3)、[数据集](https://doi.org/10.6084/m9.figshare.28457018.v4)

开发阶段已成功读取500条粤菜Excel记录；其能量对应整份配方，缺少可直接使用的成品熟重，因此未将这些记录换算成每100克食物库。首版实际采用42项USDA基础食物及50项项目示例配方，配方全部标为参考估算并保留计算依据。

香港食物安全中心的粥粉面饭研究可用于比对计量口径与有限示例，其报告有专门的再分发许可要求，不默认批量收入软件。详见[官方资料核验](中式菜肴热量官方资料核验.md)。

## 计算口径

食物热量：`实际食用克数 × 每100克热量 ÷ 100`。餐次热量与全天摄入取各条目之和，内部保留计算精度、展示时舍入，避免逐项舍入累积误差。克数必须大于0，热量允许为0；未提供的热量不得默认为0。

基础代谢相关估算建议采用成人Mifflin–St Jeor公式，注明“基础代谢估算（采用静息能量公式）”：男性参考为 `10×体重kg + 6.25×身高cm − 5×年龄 + 5`；女性参考为 `10×体重kg + 6.25×身高cm − 5×年龄 − 161`，单位kcal/天。原论文预测REE，样本19—78岁；应标明估算及适用范围，不作为个体实测值。[原论文](https://pubmed.ncbi.nlm.nih.gov/2305711/)

基础代谢估算、全天总消耗和每日摄入目标分开命名。第一版只完成用户要求的三个数值，不把“摄入 − 基础代谢 − 运动”作为真实热量缺口。

## 确认后的实施顺序

先构建并验证OpenNutriTracker固定版本，再接入核验后的本地粤菜条目和搜索，完成三餐克数、收藏/最近、独立基础代谢估算、今日手填运动、日周月统计及离线启动。重点检查克数编辑后的汇总、完整记录日的日均分子与分母、估算与完整状态分离、食物热量调整不追溯修改历史、跨周/月/年汇总、空数据与单位、重启持久化、断网首次启动和食物计量口径。

上述范围已经用户确认。功能实现和食物库边界见[离线版说明](离线版开发与使用说明.md)，最终构建和测试结果以`outputs/验证记录.md`为准。
