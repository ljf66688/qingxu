# 安卓热量记录软件：开源选型与第一版设计

核验日期：2026-10-15（北京时间）。状态：方案待用户确认，尚未编写应用代码、安装应用或部署服务。

## 推荐结论

**推荐基于 OpenNutriTracker v2.4.0 开发中文离线精简版。**

对于“中文食物/家常菜按克数分餐记录 + 独立基础代谢估算 + 手填运动消耗”的完整需求，直接安装现有应用仍有缺口；从零开发又要重新实现已经成熟的日记、食物、菜谱、历史和存储功能。复用现有应用、补齐少量关键功能，是本次调研后的工程判断，并非已完成的构建验证。

最省事的现成试用入口是 [OpenNutriTracker v2.4.0 正式发布页](https://github.com/simonoppowa/OpenNutriTracker/releases/tag/v2.4.0)，其中有 `app-release.apk`，无需 Google Play。试用安装不等同于完成本方案的定制需求。

## OpenNutriTracker 的复用边界

### 可以保留

- 分餐日记、日期切换、食物重量和每日汇总。
- 自定义食物、菜谱食材组合、按份或克数记录。
- 自定义运动，直接填写消耗 kcal，并保存常用运动模板。
- 身高、体重、生日/年龄、性别资料和体重历史。
- 简体中文基础、本地 Hive 数据存储与现有历史趋势。

证据：[正式版功能和架构说明](https://github.com/simonoppowa/OpenNutriTracker/tree/v2.4.0)、[正式版界面文案](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/lib/l10n/intl_en.arb)、[实际发布语言列表](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/lib/core/l10n/shipped_locales.dart)。文案包含运动直接填热量、菜谱总重量和每100g营养等字段；这证明已有设计入口，但不替代真机操作验证。

### 需要新增或调整

1. **独立基础代谢估算卡片。** 现版使用 IOM 2005 的 TDEE 路径，不能把现成“每日热量目标”直接改名为 BMR。官方计算文档还明确说明：以前未被调用的 BMR 实现已在 2.2.0 删除。应新增独立计算及说明，而不是假定现有代码已经满足。[计算文档](https://github.com/simonoppowa/OpenNutriTracker/wiki/Calculations)、[v2.4.0 实际计算源码](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/lib/core/utils/calc/tdee_calc.dart)
2. **中文常用食物入口。** 第一批以约100—200项经核准来源的常用食物为目标，保留来源、每100g热量、可食部分和生/熟状态；具体条目数量以数据核验为准。允许用户直接创建食物和修改自己的配方。软件翻译成中文不意味着食物库已经适合中国饮食。
3. **独立的熟重菜谱流程。** 建立“食材及用油 → 整锅熟重 → 本次吃了多少克”的流程。现成菜谱功能可复用，但总重量重开、编辑和导入后的保存需要重点验证；上游 PR 列表仍有相关修复工作，不能假定全部已经进入 v2.4.0。[上游 PR 列表](https://github.com/simonoppowa/OpenNutriTracker/pulls)
4. **离线启动与查询。** 本地食物、菜谱、记录、计算作为第一版的完整功能。原版 `initLocator()` 无条件初始化 Supabase，因此离线定制需要改造初始化及食物数据入口；不能只删除 `.env` 就宣称离线改造完成。[初始化源码](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/lib/core/utils/locator.dart)
5. **简化首页。** 默认突出摄入、基础代谢和运动消耗，饮水、断食、微量营养等功能可放入次级设置。保留现有架构，控制大范围删改，降低后续合并修复的成本。
6. **完整备份。** 上游 JSON 导出可复用，但官方文档说明用户资料、自定义食物目录等并非全在导出包里。定制版若提供“完整备份/恢复”，必须补齐并做恢复验证，不能沿用一个不完整的功能名称。[FAQ](https://github.com/simonoppowa/OpenNutriTracker/wiki/FAQ)、[导出格式说明](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/docs/export-format.md)

## 第一版产品设计

底部使用四个入口：**今日、食物与菜谱、历史、我的**。

### 今日

顶部选择日期，显示今日摄入 kcal、估算基础代谢 kcal/天、已记录运动消耗 kcal。下面依次是早餐、午餐、晚餐，可选加餐；每餐显示食物名称、克数、该项热量及餐次小计。

主操作是“添加食物”：搜索或选择常用食物 → 输入克数 → 即时预览热量 → 保存。支持调整、删除、复制昨日某餐。运动入口输入名称（可选）与消耗 kcal，默认当天，允许补记。

### 食物与菜谱

食物保存名称、每100g热量、来源、生熟状态，可选保存蛋白质等数据。常用菜谱只需配置一次，以后输入本次吃的克数即可。菜系标签如“家常菜/川菜”用于查找，热量依据具体食物和配方。

生米和熟米饭使用不同条目；油与调味品作为配方食材。液体按克或已知密度换算，不把所有液体都默认当作1g/ml。

### 历史

按日期查看每餐和运动记录，显示近7天/30天摄入趋势。历史条目保存当时的营养数值快照；修改食物库、菜谱或体重后，不悄悄改变过去已记录的结果。完整导出/恢复用于换机和备份。

### 我的

资料包括性别、**年龄或生日**、身高cm、体重kg；录入后显示估算基础代谢，并可查看公式。年龄是常用公式的必需项，不用一个隐藏的默认年龄替代。

## 计算规则

### 食物与菜谱

`食物摄入热量 = 食用克数 × 每100g热量 ÷ 100`

`一天摄入热量 = 当天各餐全部条目热量之和`

`一锅菜总热量 = 各食材（包括油）的热量之和`

`吃到的菜热量 ≈ 一锅菜总热量 × 食用熟重 ÷ 整锅可食熟重`

最后一项是产品采用的分摊估算，假定食材和油分布近似均匀。它能反映不同用油量和烹调后水分变化；剩余的油汁、丢弃部分以及挑食会造成误差。通用菜名条目标注为参考配方，用户可保存自己的版本。

### 基础代谢相关估算

建议使用 Mifflin–St Jeor 成人公式，界面标明“基础代谢估算（采用静息能量公式）”。严格而言原论文预测的是静息能量消耗 REE，不能把结果说成仪器实测 BMR。

- 男性参考：`10 × 体重kg + 6.25 × 身高cm − 5 × 年龄 + 5`
- 女性参考：`10 × 体重kg + 6.25 × 身高cm − 5 × 年龄 − 161`

结果单位为 kcal/天。该论文样本为19—78岁健康成年人，第一版定位为成人日常记录；未成年人等场景需要另行设计适用公式。[Mifflin 等原论文摘要](https://pubmed.ncbi.nlm.nih.gov/2305711/)

基础代谢/静息消耗不等于每日总消耗。第一版分别显示摄入、基础代谢估算和运动记录；如以后增加“热量缺口”，还需估算日常活动与其他消耗，并避免把同一运动重复计入活动系数和手填运动。

## 部署与开发复杂度

| 路线 | 用户需要做什么 | 后端和持续费用 | 判断 |
| --- | --- | --- | --- |
| 直接使用现成版 | 下载官方 APK、安装、录入资料和食物 | 不需要自己部署；在线食物搜索依赖项目/第三方服务 | 最快试用，但不能完整保证上述定制体验 |
| 基于现有项目开发 | 开发阶段配置工具链，交付后安装签名 APK | 本方案第一版目标无需服务器和付费API；食物、记录、计算都在本地 | **本次推荐** |
| 从零开发 | 新建安卓项目并完成全部记录、存储、备份及界面 | 同样可以无后端，但研发和验收范围更大 | 当前需求没有体现必须重写的收益 |

OpenNutriTracker 原版开发配置：Flutter 通过 FVM 固定版本，Android SDK、JDK17、`.env` 及生成文件；v2.4.0 Android 构建文件的最低 API 为26，即 Android 8.0。源码开发不是下载后直接点击运行。依赖下载速度与本机环境影响首次构建，暂未进行耗时承诺。[开发指南](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/GettingStarted.md)、[Android 构建配置](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/android/app/build.gradle)

原版食物参考库由维护者的 Supabase 托管项目提供，自建需要导入数据库、配置函数/权限和数据源；这会增加运维，第一版无需采用。仍可把 Open Food Facts 等在线搜索作为后续可选功能。[官方后端部署说明](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/docs/supabase-self-hosting.md)

OpenNutriTracker 和 Food You 使用 GPLv3，Waistline 和 Energize 的许可证见补充文档。选择 GPL 项目意味着应接受按其许可证分发修改版和提供相应源码的路线。应用代码许可与食物数据库许可分开核验；暂未找到并验证可以直接内置分发的完整中国家常菜开源数据集，不把第三方商业App的数据作为默认来源。[OpenNutriTracker 许可证](https://github.com/simonoppowa/OpenNutriTracker/blob/v2.4.0/LICENSE)

## 确认后执行范围与验收

确认项：**以 OpenNutriTracker 为基础，做 Android 8.0+ 的中文离线精简版，优先满足三餐克数、独立基础代谢估算、手填运动、自定义食物/菜谱及本地备份。**

确认后先拉取固定版本并完成原版构建，验证中文、克数、自定义运动和菜谱熟重，再开始定制。若发现构建障碍或现成功能存在重大缺陷，先以实际证据调整范围，不直接重写项目。

第一版验收重点：克数与kJ/kcal单位换算；多食物分餐与跨日补记；基础代谢公式及年龄；运动修改/删除；断网首次启动；菜谱熟重重开不丢失；历史数值不被食物库修改追溯改变；完整备份恢复后的数据一致性。

本轮核验依据官方仓库、正式发布元数据、文档与部分源码；GitHub API/搜索存在间歇限流，未完成全库扫描。没有进行安卓构建、APK安装、国内网络实测或食物库覆盖率实测，所以文中的开发难度是基于依赖与架构的评估，不能当作已经跑通的承诺。
